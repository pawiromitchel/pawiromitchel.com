Docker Desktop is a lot of app for what I actually use it for. Most days I want a Docker daemon, `docker compose`, and occasionally a UI to see which container is eating memory. The Electron app, the helper processes and the VM it keeps running in the background always felt like more than that.

[Colima](https://github.com/abiosoft/colima) covers the daemon part. It runs a small Linux VM (built on Lima) with Docker inside and wires up the normal `docker` CLI. For the UI, [Portainer](https://www.portainer.io/) runs as just another container.

This is the setup I ended up with.

## Install

Quit Docker Desktop first (or uninstall it), then:

```bash
brew install colima docker docker-compose
```

That installs the Docker CLI without the desktop app. Homebrew installs `docker-compose` as a CLI plugin, and for `docker compose` (with a space) to find it you need to tell Docker where it lives. Add this to `~/.docker/config.json`:

```json
{
  "cliPluginsExtraDirs": ["/opt/homebrew/lib/docker/cli-plugins"]
}
```

On an Intel Mac the path is `/usr/local/lib/docker/cli-plugins`.

## Start Colima

A plain `colima start` gives you 2 CPUs, 2 GB of memory and a 100 GB disk. You can size the VM to your machine instead:

```bash
colima start --cpu 4 --memory 6
```

Colima remembers these settings, so after this a plain `colima start` is enough. To change them later, stop it and start again with new flags, or run `colima start --edit` to open the config file.

A few commands I use:

```bash
colima status   # is it running, and with what resources
colima stop     # shut the VM down when I don't need Docker
colima list     # all profiles and their resources
```

Once it's up, the usual commands just work:

```bash
docker ps
docker compose up -d
```

Worth knowing: some tools don't use the Docker CLI's context and look for the socket at `/var/run/docker.sock` on the Mac itself (Testcontainers is the usual one). Colima's socket lives in your home directory instead, so point them at it:

```bash
export DOCKER_HOST="unix://$HOME/.colima/default/docker.sock"
```

## Portainer for the dashboard

The part most people miss after removing Docker Desktop is the dashboard. Portainer Community Edition fills that gap, and it runs inside Docker, so there's nothing else to install on the Mac:

```bash
docker volume create portainer_data

docker run -d \
  --name portainer \
  --restart=always \
  -p 9000:9000 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v portainer_data:/data \
  portainer/portainer-ce:lts
```

The socket path here is correct even with Colima: the container runs inside Colima's VM, and inside the VM the socket really is at `/var/run/docker.sock`. The `portainer_data` volume keeps your settings and admin account when the container is recreated.

Open `http://localhost:9000` and create the admin user straight away. Portainer locks the setup screen if nobody creates an admin within a few minutes of starting, and you have to restart the container to get it back.

From there you get containers, images, volumes, networks and logs in the browser, which covers everything I used the Docker Desktop UI for.

## Why I prefer it

- **Less running in the background.** When I don't need containers I run `colima stop` and there's nothing left running.
- **Nothing changed in my projects.** Compose files, scripts and aliases all talk to the same `docker` CLI as before.
- **The UI is optional.** Portainer is a container like any other. I can stop it, delete it or leave it running with `--restart=always`.

What you give up is Docker Desktop's extras: the built-in Kubernetes, extensions, and the one-click settings screen. Colima can run k3s (`colima start --kubernetes`) if you need a cluster. If you never used those features, you won't miss them.
